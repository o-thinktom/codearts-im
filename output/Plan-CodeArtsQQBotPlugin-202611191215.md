## 1. 计划概览

### 1.1 目标

按 TDD 冻结的形态（VSIX 容器 + sidecar 运行时 + `KernelPort` 适配层），以最小风险路径交付 P1 可用版，并在契约验证通过后推进 P2 生产版。

### 1.2 三条推进原则

1. **契约先行**：EP1（适配层）是关键路径，契约未验证前不投入大量业务代码。
2. **双轨并行**：传输层（EP2）、扩展容器（EP5）与契约轨互不阻塞，可同时开工。
3. **一次决策门**：M1 处设硬门禁，不通过则切换备选路径，避免沉没成本。

### 1.3 里程碑

| 里程碑 | 名称 | 判定条件 | 决策 |
|---|---|---|---|
| M0 | 环境就绪 | `pnpm doctor` 全绿；QQ 沙箱机器人可收发 | 可开工 |
| M1 | 契约基线冻结 | 三项硬指标通过（见 1.4） | **决策门 D1** |
| M2 | 端到端最小闭环 | 私聊文本：QQ → 内核 → QQ，重启可恢复 | 可扩大投入 |
| M3 | P1 可用版 | 群聊/白名单/流式/绑定 UI/命令全部验收 | 可内测 |
| M4 | P2 生产版 | 审批/媒体/诊断/兼容矩阵全绿 | 可灰度 |
| M5 | 发布 | 市场审核通过 / 侧载包签名完整 | 正式发布 |

### 1.4 决策门 D1（唯一致命分支点）

| 硬指标 | 通过标准 | 不通过时的备选 |
|---|---|---|
| 独立会话创建 | 能为不同 peer 创建互不干扰的 session，并能 resume | B1：扩展桥接同进程客户端 |
| 完成消息可得 | 能稳定拿到 `message/complete`（含文本块） | B1；仍失败则 B2 |
| 事件可归属 | 能区分 `turn` 与 `session`，不串话 | B1 |
| 审批可回传（加分项） | 外部可应答 permission | 不阻塞 M2，降级为静态策略 |

**D1 切换成本控制**：EP2/EP4/EP5/EP6 的产物与后端无关，切换只影响 EP1 的 `http-port` 与 EP3 的部分编排，预计损失可控。B2（Space 渠道）则整案转向，需产品重新立项。

## 5. 质量计划

### 5.1 测试分层

| 层 | 范围 | 工具 | 门禁 |
|---|---|---|---|
| 单测 | qqbot-core 纯逻辑 | Vitest | 覆盖率 ≥85% |
| 契约 | kernel-port 回放 | Vitest + fixtures | 8 类事件断言全绿 |
| 集成 | runtime + mock QQ + mock kernel | Vitest | 关键路径 12 条用例 |
| 扩展 | 命令/视图注册、激活 | `@vscode/test-electron` | 无异常激活 |
| E2E | 真实码道 + 真实 QQ 沙箱 | 脚本 | 核心 6 场景 |
| 安全 | 越权/穿越/重放/凭据 | 人工 + 脚本 | 高危清零 |
| 稳定 | 24h 压测 + 故障演练 | 脚本 | 零崩溃、自愈成功 |

### 5.2 每批次必过门禁

    lint → typecheck → 单测 → 契约回放 → 集成 → 打包 → mock 冒烟 → 依赖方向检查

任一项失败即阻断合并；**不允许"下批次补"**。

### 5.3 核心 E2E 场景（M2/M3 必测）

1. 私聊发"你好" → 收到完整回复。
2. 私聊发代码块 → 回复代码块不被切裂。
3. 群聊不 @ → 无响应；@ → 正常回复且带发送者标签。
4. 重启 IDE → 再次对话 → 历史延续。
5. 白名单外用户 → 被拒且审计留痕。
6. 断网 2 分钟 → 恢复后消息不重复、不丢失。

### 5.4 每个任务的完成定义（DoD）

1. 代码 + 单测（或契约用例）。
2. 结构化日志（含 `sessionKey`/`turn`/`callId` 可见）。
3. 错误码登记（新错误必须落 `errors.ts`）。
4. 配置项/文档同步更新。
5. 通过本批次门禁。
6. 评审通过（至少 1 名非作者）。

## 8. 度量与跟踪

| 指标 | 目标 | 采集方式 |
|---|---|---|
| 里程碑按期率 | 100%（允许调范围，不允许调门禁） | 批次回顾 |
| 契约用例通过率 | 100% | CI |
| 单测覆盖率（core） | ≥85% | CI |
| 缺陷密度 | 发布前高危为 0 | 缺陷库 |
| 平均修复批次 | ≤1 批次 | 缺陷库 |
| E2E 通过率 | 100% | 发布前跑 |
| 队列/延迟基线 | 与 TDD 1.5.2 对齐 | T8.5 报告 |

### 8.1 沟通机制

| 机制 | 频率 | 产出 |
|---|---|---|
| 批次计划会 | 每批次开始 | 任务认领、依赖确认 |
| 契约同步会 | 每周 / 内核变更时 | 映射表 diff、影响评估 |
| 门禁评审 | 每批次结束 | 通过/阻断结论 |
| 风险复盘 | 里程碑后 | 风险登记表更新 |

### 8.2 契约变更流程（强制）

    内核侧变更通知 → TL 评估影响面 → 更新「事件映射表」→ 更新 fixtures
      → 契约测试红灯 → 修改 normalize/compat → 回归全绿 → 才允许合入业务代码

**禁止**先改业务代码再补测试。
