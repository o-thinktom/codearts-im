# codearts-im

> CodeArts IM Gateway · Автор: ThinkTom · MIT

[简体中文](README.md) | [English](README.en.md) | **Русский** | [فارسی](README.fa.md) | [Türkçe](README.tr.md) | [Español](README.es.md)

IM-шлюз для локального **Huawei Cloud CodeArts Agent**: одно сообщение с телефона — и агент в настольной IDE выполняет задачу и возвращает результат. Поддерживаются каналы **QQ, WeChat (iLink) и WeCom (корпоративный WeChat)**; активен один канал, учётные данные хранятся в системном хранилище секретов.

## Возможности

- **Три канала**: QQ (официальный коннектор), WeChat iLink, WeCom (`@wecom/aibot-node-sdk`)
- **Подключение по QR-коду**: без ручного ввода ключей; ручной ввод — только как резерв
- **Управление сессиями**: отдельная сессия ядра на собеседника, сохранение и восстановление после перезапуска IDE
- **Надёжная доставка**: объединение шагов, разбиение по Markdown и лимитам канала, деградация при ошибках
- **Потоковые ответы**: WeCom поддерживает增量 (дельта-кадры с троттлингом 600 мс)
- **Взаимодействие**: подтверждения (`1` / `2`) и вопросы (`A/B/C`); решение принимает только собеседник сессии
- **Только итоговый ответ**: рассуждения, системные подсказки и шум инструментов фильтруются
- **Медиа**: входящие изображения и файлы скачиваются и расшифровываются на диск; исходящие — по возможностям канала
- **Контроль доступа**: open / allowlist / disabled, коды сопряжения, отзыв, блокировка одного экземпляра
- **Наблюдаемость**: журнал sidecar на диске, диагностический пакет в один клик (с маскированием и матрицей совместимости)

## Возможности каналов

Таблица возможностей задаётся в `packages/qqbot-runtime/src/transport/capabilities.json`; адаптеры не объявляют значения самостоятельно.

| Канал | Лимит символов | Поток | Индикатор ввода | Кнопки | Медиа | Группы |
|---|---|---|---|---|---|---|
| QQ | 4500 | — | — | — | загрузка base64 | Да (по умолчанию с @) |
| WeChat iLink | 1800 | — | Да | — | зашифрованный CDN | Только личные |
| WeCom | 3500 | Да | — | Не реализовано | загрузка через SDK | Да |

### Границы отправки файлов

**Активная отправка файлов** работает во всех трёх каналах. **Автоматическая отправка файла вместе с ответом** пока не поддерживается:

- ядро не отправляет события о результатах (`round.artifacts.updated` объявлено, но не приходит);
- реализованы резервные пути: локальные `file://` изображения и PDF, открытые через `browser`, а также маркеры `![alt](path)` и `[[file:path]]`;
- если канал отклоняет файл, в ответ приходит `не удалось отправить файл: <причина>` — без молчаливой потери.

## Архитектура

    QQ / WeChat iLink / WeCom
      ↕  (WebSocket / длинный опрос HTTPS)
    sidecar (единый бинарник Node SEA)
      ↕ локальный IPC (именованный канал + одноразовый токен)
    Расширение VS Code (VSIX)
      ↕ локальный HTTP + SSE
    Ядро CodeArts Agent (Session / Tools / Permission / Skills)

- Учётные данные и ядро остаются на локальной машине; sidecar не открывает публичный порт;
- `KernelPort` — единственная точка связи с ядром; каналы находятся в `adapters/{qq,weixin,wecom}`;
- Расширение отвечает за жизненный цикл, QR-подключение, поиск порта ядра, расшифровку пароля и переключение канала.

## Совместимость

| Компонент | Поддержка | Примечание |
|---|---|---|
| ОС | Windows 10 1809+ / Windows 11 (x64) | Артефакт win32-x64; для macOS/Linux нужна сборка на целевой платформе |
| CodeArts Agent | ≥ 26.11.100 | Проверено на 26.11.x |
| Ядро агента | 126.11.x | Проверено на `126.11.2-20261117200150` |
| VS Code API | `^1.109.0` | Только стабильные API |
| QQ Open Platform | Bot WebSocket API v2 | Песочница или production-бот |
| WeChat iLink | Протокол 2.4.6 (`bot_type=3`) | Нужен сканер в мобильном WeChat |
| WeCom | WebSocket умного бота | Нужен бот, разрешённый администратором |
| Node.js (только разработка) | ≥ 20.3 | Конечным пользователям не нужен |

Проверка совместимости:

    npm run compat                      # только чтение + сессия + проверка каналов
    npm run compat -- --im wecom        # проверить один канал
    npm run compat -- --with-prompt     # добавить один реальный запрос (расход квоты)

Результат пишется в `compat-matrix.json` и может быть включён в диагностический пакет.

## Установка

Требования: Windows x64, CodeArts Agent 26.11.x. Node.js **не** требуется.

    & "<каталог CodeArts>\bin\codearts-agent.cmd" --install-extension "<путь>\codearts-qqbot-cn-0.3.2.vsix"

Также можно установить из панели расширений («Install from VSIX»), затем «Developer: Reload Window».

> Перед обновлением завершите старые процессы: `taskkill /IM qqbot-sidecar-win32-x64.exe /F`, чтобы освободить IPC-канал.

## Быстрый старт

1. Запустите CodeArts Agent и завершите один диалог, чтобы ядро работало;
2. Выполните команду подключения нужного канала:
   - «QQ Bot: 扫码绑定机器人» — QQ
   - «QQ Bot: 扫码绑定微信» — WeChat
   - «QQ Bot: 扫码绑定企业微信» — WeCom
3. Отсканируйте QR-код и подтвердите авторизацию на официальной странице;
4. Учётные данные попадут в системное хранилище, `im/channel` переключится, плагин перезапустит соединение;
5. Отправьте сообщение боту в соответствующем IM.

Примечания:

- Одновременно активен только один канал; старые учётные данные сохраняются — чтобы вернуться, отсканируйте код снова;
- Если сканирование недоступно, используйте «QQ Bot: 手动填写凭据»;
- Первый запуск sidecar занимает 5–10 с (распаковка SEA); панель подключения ждёт автоматически.

## Настройки

| Параметр | По умолчанию | Описание |
|---|---|---|
| `codeartsQqbot.enabled` | `false` | Запускать sidecar вместе с IDE |
| `codeartsQqbot.provider` | `inferhub-provider` | Провайдер модели |
| `codeartsQqbot.model` | `deepseek-v4.1-flash-1017` | ID модели; не оставлять пустым |
| `codeartsQqbot.agent` | `build` | Имя агента |
| `codeartsQqbot.access.c2cMode` | `open` | Режим доступа в личных сообщениях |
| `codeartsQqbot.access.groupMode` | `allowlist` | Режим доступа в группах (рекомендуется) |
| `codeartsQqbot.textChunkLimit` | `4500` | Максимум символов (лимит канала важнее) |
| `codeartsQqbot.media.maxMB` | `200` | Лимит входящих медиа |
| `codeartsQqbot.sendFile.restrict` | `true` | Ограничивать пути исходящих файлов |

## Безопасность и данные

- AppSecret / токен WeChat / секрет WeCom хранятся только в системном хранилище или памяти;
- Пароль ядра читается из официального зашифрованного хранилища только для чтения, с ручным резервом;
- Исходящие файлы проверяются по белому списку рабочей области (`realpath`), до 20 МБ;
- Журналы и диагностика маскируют секреты, токены и openid (повторное `[REDACTED]` перед экспортом);
- В IM отправляется только итоговый ответ;
- Подробнее: [PRIVACY.md](PRIVACY.md).

## Диагностика

- Журнал: `<globalStorage>/codearts-community.codearts-qqbot-cn/qqbot/logs/sidecar.log` (4 МБ × 5)
- Экспорт: «QQ Bot: 导出诊断包» — состояние расширения и sidecar, канал IPC, снимок настроек, 300 строк журнала и матрица совместимости
- Панель вывода: `CodeArts QQ Bot`

| Запись | Значение |
|---|---|
| `sidecar binary not found` | В VSIX нет `bin/`; переустановите |
| `ipc bridge connected` | Расширение и sidecar соединены |
| `sidecar running` / `channel online` | Сервис и канал готовы |
| `inbound accepted` / `kernel prompt sending` | Передано ядру |
| `reply sending (stream finish)` | Потоковый ответ завершён |
| `sendFile failed` | Ошибка отправки файла, причина в ответе |
| `listen EADDRINUSE` | Остался старый sidecar; выполните `taskkill` |

## Ограничения

- Артефакты только для Windows x64;
- Сильная зависимость от версий CodeArts Agent и ядра;
- QQ: окно пассивного ответа около 5 минут, не более 5 ответов на сообщение;
- WeChat iLink: только личные сообщения; `ret=-14` требует повторного сканирования;
- WeCom: карточки с кнопками не реализованы, используется текст;
- Группы по умолчанию allowlist;
- Автоматическая отправка файлов ограничена платформой.
